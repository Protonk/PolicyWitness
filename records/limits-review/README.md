# Where users find PolicyWitness limits

The worksheet `decisions.tsv` carries one row per limit. **Agreed** records a destination for the combined proposal. **Follow-up** reserves the destination decision for a named investigation. **0.3.9 follow-up** marks a reviewed question or shared deliverable due before release. **0.4.0 follow-up** reserves a reviewed question for that release. **Open** marks the remaining rows for review. Review the whole proposal before implementing the selected routes. [Limits review plan](../../docs/LIMITS-SURFACING-PLAN.md)

## Decisions due before release

**0.3.9 follow-up — `equipment_error_domain`.** Decide before releasing 0.3.9 whether this belongs in LIMITS and how to account for it. For an equipment `NSError`, the host retains complete Swift Characters up to 128 UTF-8 bytes of the domain and carries the numeric code. The receiver separately checks the length of a supplied domain. Compare two distinct native domains with the same retained prefix and code, then compare a supplied report whose domain exceeds the bound. What error identity can a reader establish in each case? Use the answer to settle whether the item is a user-facing limit, a rule for preserving diagnostic identity, or warrants another disposition. Record the decision and its rationale here.
