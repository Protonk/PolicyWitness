## K-135-1 · C:135 · example

**Pass.** examples-request
**Claim.** "file `open_write` opens with truncation"
**Mechanism.**
1. The request names `attempt: {kind: "file", action: "open_write", target}`. The action string is the Swift constant `PWRunnerWire.attemptActionOpenWrite`.
2. In the XPC host, request planning maps (`file`, `open_write`) to the Swift enum case `.fileOpenWrite`, raw value 2, which is written into the worker's shared-memory slot.
3. The C worker (`pw-probe-runner`), after applying the policy, dispatches on the slot's kind: `PW_ATTEMPT_FILE_OPEN_WRITE` (C enum value 2) calls `attempt_file_open_write`.
4. `attempt_file_open_write` calls `open(slot->target, O_WRONLY | O_TRUNC)`. On failure it records errno through `fail_from_errno`. On success it records the observed path, writes one byte `'x'` (the write result is discarded), closes, and sets `rc = 0`. There is no `O_CREAT`: an absent target fails.
The worker decides the flags; the host only selects the action. Copies: the action number is declared twice, by hand, in Swift (`CWorker.swift` 285) and C (`pw_probe_runner_abi.h` 133). INFERRED: the `runner_abi_layout` suite checks their agreement (not opened). The Python effect test carries its own hand-written expectation table. INFERRED: the actor form reaches the same C function through the same worker binary and slot kind (`ActorSession.swift` spawns `workerExecutablePath`; its slot construction was not read).
