# Independent implementation account — before the worker tour

Frozen review revision: `5124b4309b6f7b0041c55318312a9ee18f579868`.

This account was derived before opening `docs/WORKER.md` or the worker capability graph. I read my assignment, root/controller/runner guidance and orientation, the selected frozen implementation, and relevant wire/evidence contracts. I did not build, run tests, inspect sibling reports, or inspect `docs/WORKER-INST-DOC-PLAN.md`. All line numbers below name the frozen revision, not the current checkout. This is a source account, not an execution claim. Private sandbox and native-library internals remain unknown.

## Process and resource account

1. **Admission and preparation in the unsandboxed host.** `CWorkerOrchestrator.run` repeats capacity/meaning admission, flattens ordinary and extension actions into ordered slots and contiguous phase partitions, creates an optional `ExtensionSession`, and passes only an eligible delivery descriptor to the worker (`CWorkerOrchestrator.swift:65–158`). Missing issuer/native capability returns a named refusal; ordinary preparation/issuance failures can continue with an extension declaration but no token descriptor. The session resolves and stats the extension target before worker creation; that records a path/identity at preparation time, not a frozen future object (`ExtensionIssuer.swift:40–76`).

2. **Ordinary-authority issuer.** The session creates mode-0600 shared memory, immediately attempts unlink, sets CLOEXEC, truncates/maps/zeros it, and copies the resolved target. A high duplicate avoids descriptor collisions. Issuer spawn uses CLOEXEC_DEFAULT, channel FD 3, and `/dev/null` on all stdio (`ExtensionIssuer.swift:63–105`). The C issuer disables core dumps, verifies/maps FD 3, calls `close(3)`, loads libsandbox and resolves issue/consume/release, publishes a marker before issue, uses the fixed read class and flags 0, bounds/copies the token, erases its native allocation, and publishes completion (`pw_extension_issuer.c:16–53`). Close/unmap returns here are not independently published. Host delivery requires valid bounded publication, exit code 0, and a reap during the main issuer wait; timeout/failed cleanup cannot qualify a token (`ExtensionIssuer.swift:107–166`). Issuer final termination uses the common child observer and may block after successful SIGKILL. Host erasure is separately recorded and repeated at deinit; it is not proof of erasure in all native copies.

3. **Worker spawn resources.** `runCWorker` validates inputs before allocating (`CWorker.swift:898–913`). It opens a PID-derived named shm object, attempts immediate unlink, clears its CLOEXEC flag, sizes/maps/zeros it, populates exact source byte count, identities, parameters, phases, slots and optional capture nonce, touches host pages, then release-publishes `prepared` (`915–1045`). These are host touches, not a worker residency guarantee. Host creates ready and policy pipes, suppresses SIGPIPE on the policy writer, makes it nonblocking, and sets CLOEXEC on all pipe ends. An optional extension descriptor gets a high CLOEXEC duplicate. File actions deliver policy on FD 0, evidence mapping on 3, ready writer on 4, token channel on 5. Worker spawn passes nil attributes/environment, not CLOEXEC_DEFAULT (`1047–1141`). It does not pre-open ordinary attempted files or exec attempt resources. The worker can still inherit host descriptors not otherwise marked CLOEXEC. Worker spawn file-action initialization/add calls are not all checked.

4. **Policy delivery and worker bootstrap.** The host transfers its single policy byte array under one absolute post-spawn deadline, closes the writer, then has a separate readiness wait; transfer failure skips ready/sentinel polling but still requests exit and collects cleanup/publications (`CWorker.swift:1143–1242`). The worker ignores SIGPIPE, parses args, starts timing, fstats/maps shared memory, checks bootstrap magic/source identity before using the ABI, validates `prepared`, count and phase partition, then prepares the extension (`pw_probe_runner.c:1557–1651`). No evidence map descriptor close/unmap occurs in the ordinary worker lifetime; process teardown releases it. Header/count/clock/read failures can exit before `done`.

5. **Extension endpoint acceptance precedes application.** `prepare_extension` resolves consume/release first, disables core dumps before mapping token bytes, inspects size, maps and closes the descriptor once, validates channel magic/publication/status/length/terminator, and independently publishes delivery (`pw_probe_runner.c:1268–1351`). Unavailable API, absent token, rejected content and local syscall failure remain distinct. Earlier failure attempts close; mapped rejection erases token bytes and attempts unmap; cleanup close/unmap failure has its own fields. A failed close is not retried and descriptor absence is not proven. Accepted mapping remains through consume/normal completion; delivery is evidence of accepted channel bytes, not native consumption. Host supplies one retained session; worker/header token state is separate from evidence mapping.

6. **Compile/apply.** Before policy read, worker snapshots the expected length. EOF publishes actual received count; overflow/read error has no EOF receipt. Length mismatch and embedded NUL refuse compile. Params are bounded and snapshotted before native use; allocation/set failure publishes operation-specific failure and a nonzero summary, then `done` and exit spin. Compile uses the consumed source/params; parameter cleanup follows compile; compiler null and diagnostic have independent publications (`pw_probe_runner.c:1663–1833`). Optional capture copies the same compiled object before apply, without a pipe. The ready byte precedes apply and failure does not stop application. `sandbox_apply` is called once; native failure records errno, publishes `done`, and spins. Success release-publishes `applied` (`1835–1901`). The profile object remains until process death; no post-apply profile free is attempted. Receipt exposure has stricter host success/completion/PID/nonce/hash/extent checks (`CWorker.swift:556–595`). Private compiler allocation/layout behavior is not established by this source alone.

7. **Phase barrier.** Worker release-publishes each arrival, validates continuous-clock samples and timeout arithmetic, rejects expiry/future ordinal/clock faults before acknowledgement, and observes exit cancellation. Correct ordinal updates the exec-plan deadline to exclude this wait and publishes acknowledgement before any attempt (`pw_probe_runner.c:1487–1552`). Host checks applied/rc/identity/arrival, prior completion and premature publication, observes child ownership, invokes fresh phase planning and bounded validator collection, marks closure, rechecks child/live phase, then release-stores the ordinal (`CWorker.swift:1213–1343`). Collection failure can still be followed by attempts; it does not fabricate a prediction. No eligible queries means no validator. A collection can exceed worker wait, so closure alone never guarantees release/acknowledgement. Comparison order additionally depends on eligible native records and these phase/lifetime facts (`CWorkerOrchestrator.swift:926–1054`).

8. **Attempts and native scope.** Each slot is initialized, dispatches exactly its action, then release-publishes completion; a kill-before-publication seam withholds returned-but-unpublished payload (`pw_probe_runner.c:1413–1449`). The global progress word marks wrapper entry/return, not every native call. Ordinary `rc` is PW status, not generally a native syscall return (`CWorkerOrchestrator.swift:805–901`). `open_read` opens, records best-effort F_GETPATH, attempts one byte read and close but ignores their returns; `open_write` truncates and similarly ignores one byte write/close. `create` opens/creates without O_EXCL/truncation. `access` is R_OK only. Mach lookup obtains bootstrap port, calls bootstrap_look_up, deallocates the returned service right on success, and does not explicitly deallocate bootstrap right; return codes are diagnostic text. Sysctl does one bounded local buffer call (`pw_probe_runner.c:641–758`). `read_fresh` alone publishes individual open/stat/read/close returns plus descriptor identity and bounded bytes (`1380–1406`).

9. **Exec branch.** Clock/budget admission precedes post-apply acquisition of two pipes and spawn handles. Setup failure names its actual call and attempts partial cleanup; setup/close/destroy handling does not independently prove every resource release. Child gets empty environment, `/dev/null` stdin, captured stdout/stderr, CLOEXEC_DEFAULT, and its own process group. Spawn uses an absolute target. After spawn, the worker tracks pipe EOF and leader exit separately, retaining an unreaped leader with WNOWAIT while group signaling is still authorized. Timeout/observation/clock faults can request group kill; descendants can leave the group, and normal leader exit/EOF does not prove all descendants ended. Reaping is bounded/nonblocking, results require successful wait, and errors coexist with captured output. Blocking setup/spawn calls are not interrupted by the deadlines (`pw_probe_runner.c:782–1210`).

10. **Extension actions.** A pre-call marker is published only after token/handle/API/one-shot eligibility. Native consume/release result and errno become reportable only with slot completion; interruption after marker or return does not publish a result. Successful consume means result != -1 supplies a handle; release does not assert revocation effects. Consume erases mapped token bytes after its decision; normal plan completion also erases them. Failure/death before those paths relies on host erase/process teardown, not a worker cleanup publication (`pw_probe_runner.c:1354–1375,1915`; `CWorkerOrchestrator.swift:208–236`).

11. **Failure and teardown.** Early bootstrap/read refusals return directly; params/compile/apply/wait refusal paths publish then CPU-spin for exit. Normal slots -> phase completion -> token erase -> optional hang/signal seam -> `done` -> CPU-only spin; `_exit(0)` is attempted only once exit_requested is observed (`pw_probe_runner.c:1467–1475,1903–1945`). Host records why polling stopped before exit request, gives grace, may request SIGKILL, and keeps kill and reap facts separate. ECHILD stops further ownership-dependent kill/wait; successful kill may lead to a blocking final wait, and failed cleanup can leave a live child/zombie (`CWorker.swift:843–895,1346–1385`). Final acquire snapshot retains immutable late publications with collection basis `after_confirmed_reap` or `execution_may_continue`, without changing the stop reason. Only completed slots yield payloads (`1387–1514`). Session erasure occurs before reply assembly; host mapping/fds use defer/deinit cleanup whose ordinary close/unmap success is not generally recorded.

## Limits to carry into the comparison

- No execution evidence has been credited; source reachability and intended native calls are not observed behavior.
- Descriptor placement must distinguish a spawn action from proof of child receipt, and failed close/unlink from proven resource absence.
- Native publication is strongest for selected failures, extension actions, ready write, policy receipt and read_fresh. Ordinary attempt summaries do not preserve all native returns; progress is not a native-entry marker.
- Private native API allocation, authority transitions, kernel authorization and effects are unknown beyond observed returns and independent witnesses.
- Cleanup attempts differ from cleanup success. Shared child termination can block, exec cleanup is group-scoped, and process death is part of the resource design.
- I have not exhaustively traced validator implementation, controller admission, compiled-profile layout internals, or every disposition classifier rule. Those limits do not invalidate the directly traced resources/branches.
