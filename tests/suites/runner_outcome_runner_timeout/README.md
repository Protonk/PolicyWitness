# runner_outcome_runner_timeout

Drives `normalized_outcome = "runner_timeout"` end-to-end by combining
`_test_overrides.worker_timeout_ms = 2000` with
`_test_overrides.worker_post_apply_hang_ms = 8000`. The C worker
survives sandbox apply but hangs in `pw-probe-runner`'s post-apply
seam; the host's deadline and reap grace expire, and the host SIGKILLs it.

This case deliberately uses an empty plan: timeout handling must work without
attempts or a validator child. The other CLI timeout cases exercise completed
observations, using the same suite-local `check.py`:

- `runner_use_c_worker/worker_timeout_ms_honored`: one allowed write.
- `witness_contract/worker_post_apply_hang_seam`: an allowed write and a denied
  write, distinguishing attempt completion from attempt success.

Both populated cases independently read and retain file bytes before decoding
the envelope. The allowed file must change to nonempty content; the denied file
must retain every seed byte. Completed steps retain their IDs/order, prediction
and attempt paths, outcomes, errno evidence, compatibility aliases, and
`drift=false` for allow/success and null for unattributed failure. The validator exits cleanly and `partial_steps=false` even though
the run times out. Expectations are supplied by the test, not PW's response.

## Invariants

- The host shortened the worker's life (SIGKILL after its reap grace) rather
  than waiting for the worker's ~8s natural sleep. This is proven
  deterministically by the envelope — `runner_timeout` + `term_signal == 9`
  + no exit code — not by wall-clock: a worker that completed its
  hang would have flipped `done` and clean-exited (`ok`, `exit_code == 0`).
- `term_signal == 9` (SIGKILL, host-issued). Host-issued termination is
  classified as `runner_timeout`.
- All three cases use a 2-second worker deadline and an 8-second hang, leaving
  ample margin beyond the deadline and 1-second reap grace for the kill path.

## Success criteria

- CLI exit 1, `result.ok == false`, and runner `rc == 1`.
- `runner_result.normalized_outcome == "runner_timeout"`.
- The error identifies `pw-probe-runner`, its sentinel deadline, and host SIGKILL.
- `runner_subprocess.term_signal == 9`, no exit code, and `partial_steps == false`.
- Sandbox application succeeded; the top-level PID matches the worker PID.
- Both timeout and hang overrides match the specimen.
- An explicit `runner_result.steps == []` and no validator subprocess metadata.
  Optional subprocess fields may be absent or null.

The run uses `--no-log-capture`: the test reads only `runner_result`
fields, and skipping the post-run `log show` scan keeps it independent of the
host's unified-log archive size. The 20-second client timeout and 25-second
harness wait are outer bounds, separate from the worker deadline under test.

## Fixtures

- Specimens generated by `check.py`; populated cases use fresh temporary files
  with random names, IDs, and seed bytes.

## Artifacts

- `tests/out/suites/runner_outcome_runner_timeout/<test_id>/artifacts/*`
- Each caller retains `specimen.json`, `expectations.json`, raw `run.json`,
  `pw.stderr`, `capture.json`, and `assert.log`. Populated cases also retain
  `file<N>.before` and `file<N>.after` byte snapshots.

## Run

```
./tests/run.sh --suite runner_outcome_runner_timeout
```

Suite runs in a few seconds (the 2s host deadline + reap grace; no log scan).
