## K-243-4 · C:243 · evidence

**Pass.** gates-lifecycle-profile
**Claim.** "…nonce … must be consistent."
**Mechanism.** Producer only (label PROFILE-PRODUCER, used by rows 36-38; one function, `decodeProfileCapture`, checks nonce, worker PID, extent and digest in sequence).
1. Request admission requires `capture_nonce` to be 32 lowercase hex characters when capture is requested and refuses a nonce without capture (`invalid_capture_nonce`, `inapplicable_field`). `ActorSession` refuses before spawn if the nonce does not parse.
2. The host writes the 16 nonce bytes into the worker's shared-memory header. The C worker copies the header nonce into its capture record with its own PID, lengths and digests.
3. After the worker finishes, `decodeProfileCapture` returns `unavailable` with a reason unless, in order: apply succeeded; the worker completed with exit 0; the capture completed; the worker's capture status is 1; the recorded PID equals the worker PID; the recorded nonce equals the request nonce (`capture_nonce_mismatch`); type 0 and 0 < length <= capacity; SHA-256 of the bytes equals the recorded digest; source length and digest and parameter count and digest equal the host's own.
4. A `captured` receipt carries `request_nonce` as the request's own string.
No reader compares the nonce. `controller/src` does not reference `request_nonce` outside the generated records and one test that sets it to `None`; `_validate_capture` does not read it. The guide assigns the join to consumers (`docs/PolicyWitness.md` 670-672).
**When it does not hold.** changed by the producer — the receipt becomes `status: "unavailable"` with `reason: "capture_nonce_mismatch"` and `worker_pid`, with no bytecode, producer, stage or nonce; the reply is otherwise published normally. On the reader side: not checked. A reply carrying a `captured` receipt with a different or absent nonce is admitted by the controller (the unit test at `porcelain_admission.rs` 2713-2742 asserts no admission problem with `request_nonce: None`).
**Sources.** `runner/Sources/PWRunnerCore/ProbeRunner.swift` (65-69); `ActorSession.swift` (71-72, 153-154, 737-741); `CWorker.swift` : `captureNonceBytes` (671-676), `decodeProfileCapture` (678-716); `controller/tools/pw_probe_runner/pw_probe_runner.c` (1531-1532, 1600; grep lines only); `controller/tools/pw_probe_runner/pw_profile_capture.h` : `pw_capture_profile` (60-89); `controller/src/porcelain_admission.rs` (1289-1312).

## K-243-9 · C:243 · example

**Pass.** examples-reply
**Claim.** "a wrong nonce refuses the receipt even inside a current reply"
**Mechanism.** No reader refuses a receipt because of its nonce. What exists is a producer-side comparison in the XPC host, made before the reply is built, plus a request-admission check on the nonce's format.
1. Request admission (Swift host, `ProbeRunner.swift:65-69`): when `capture_compiled_profile` is set, `capture_nonce` must be 32 lowercase hex characters (`captureNonceBytes`), else the request is refused with code `invalid_capture_nonce`; a nonce without the capture flag is refused as `inapplicable_field`. `ActorSession.swift:71-72` repeats the format check and fails with `captureNonceInvalid`.
2. Host to worker: the host writes the 16 nonce bytes into the shared-memory header (`ActorSession.swift:153-154`, offset `PWShmLayout.captureNonceOffset` = 40). The C worker copies `hdr->capture_nonce` and passes it to its capture routine (`pw_probe_runner.c:1531-1532, 1600`; seen by search, routine not opened), which stores it in the capture record's `request_nonce` field (offset 128, `PWShmLayout.captureRequestNonceOffset`).
3. Host collection (`decodeProfileCapture`, Swift): in order it requires successful application, worker completion with exit 0, the capture-completed flag, capture status 1, capture worker pid equal to the observed worker pid, then `captureNonceBytes(nonce)` non-nil and equal to the 16 bytes at offset 128; on a difference it returns `CompiledProfileCapture(status: "unavailable", reason: "capture_nonce_mismatch", worker_pid:)` with no producer, stage, nonce, digest or bytecode. Extent/type, payload digest and consumed-input checks follow. Only if all pass does it return `status: "captured"` with `producer: "worker"`, `capture_stage: "before_apply"`, `request_nonce: nonce` (the request's nonce string, not the bytes read back) and the bytecode.
4. So on a nonce difference the receipt is still published, as `unavailable` with a reason. The run is not refused by this function.
5. Readers of a reply check only context, in three hand-written copies: Swift `CompiledProfileCapture.contextProblem` (host reporting self-check), Rust `porcelain_admission::admission_problem` (controller), Python `consumer._validate_capture` (harness). Each requires `status` in {`captured`, `unavailable`}; `captured` needs `producer == "worker"` and `capture_stage == "before_apply"`; `unavailable` needs both absent. None reads `request_nonce`, `worker_pid`, `bytecode_length` or `bytecode_sha256`, and none has the request's nonce available to compare. In the controller a context failure yields `ReplyVersion::Malformed` -> outcome `malformed_runner_response`, exit 1 (`run_flow.rs:100-103, 353-356`).
6. Consequently a reply with the current producer contract carrying a `captured` receipt whose `request_nonce` differs from the request's would be admitted by the controller (INFERRED from `admission_problem`; supported by the unit test that admits a `captured` receipt with `request_nonce: None`).
**Who acts, and what a consumer observes.** The host (producer) acts, before the reply exists, by publishing a different receipt: a consumer sees `compiled_profile.status == "unavailable"`, `reason == "capture_nonce_mismatch"`, and no `request_nonce`, `bytecode` or digest; the reply itself is not refused on that account. No reader of a reply refuses or flags a receipt for its nonce.
**Sources.** `runner/Sources/PWRunnerCore/CWorker.swift` : `captureNonceBytes` (671-676), `decodeProfileCapture` (678-716; nonce comparison 693-696), layout constants (69, 99, 143); `runner/Sources/PWRunnerCore/ActorSession.swift` (71-72, 153-154, 738-741); `runner/Sources/PWRunnerCore/ProbeRunner.swift` (65-69); `controller/tools/pw_probe_runner/pw_probe_runner.c` (1531-1532, 1600); `runner/Sources/PWRunnerCore/PWRunnerProfileCapture.swift` : `contextProblem` (30-43), `validateForReporting` (44-48); `controller/src/porcelain_admission.rs` : `admission_problem` (1289-1312); `tests/lib/consumer.py` : `_validate_capture` (538-551).
