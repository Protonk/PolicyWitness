# What the caller or reader still has to decide

November 23, 2026 · Source reviewed through `2bc70a43` · Writer's handoff for the guide and release. The maintainer will decide on independent trace review after reading the guide.

The practical question is what a recipient can establish with a specimen and an envelope. Each row identifies the occasion, the caller's next action and the mistake that action prevents. U-numbers locate the candidates in the trace working notes. The examples in draft 0 teach the common cases. The field-specific reading rules stay in the references. [Draft guide](../docs/guide/PolicyWitness.md) · [User responsibilities](../docs/REQUIREMENTS.md)

## Before authorizing execution

| When and who | What to do and why | Basis and scope |
| --- | --- | --- |
| A specimen author wants a particular request interpreted (U-01, U-02, U-08) | Write each name once in its JSON object. Use distinct, nonempty step IDs in both forms. Canonically equivalent names can collide. After a `bad_request`, repair the first reported `data.request_failure.code` and `.path`. A null dossier path can also accompany a refused option value. Save the command when the location matters. | Signed admission corpus and actor repair, build 1666. Ordinary form can admit a unique empty step ID. Actor form refuses it. Duplicate-name acceptance and choice of value are unspecified. [Request](../docs/REQUEST.md) |
| The author wants to check a repair before allowing its effects | An accepted `run` starts execution. Try a disposable target and review helper arguments if the real effects must wait. A fixture trial exercises that edited specimen. On the real target, the first successful resubmission can create the file. | With the invalid second actor step, the first step's file stayed absent. Repairing only the identifier allowed the signed app to create the file. The admission-only diagnostic has no shipped command. [Repair example](../docs/guide/PolicyWitness.md#repairing-a-refused-specimen) |
| A caller compares builds or reuses an external service (U-49, U-50) | Keep the app's contract and the equipment readback with the result. Review the specimen against a changed development contract before reasserting it. Reinstall a service from the matching app when its identity is stale. A development digest covers selected paths and bytes on disk. Use provenance and signatures for claims about the revision, tools or signer. | R3's traversal refusals and literal-tree identity controls. A changed test input can change the digest. [Build identity](../docs/BUILD.md) |

## Reading a step or an effect

| When and who | What to do and why | Basis and scope |
| --- | --- | --- |
| A recipient wants to explain an application error (U-03) | Locate the published worker call, its result and operand. Read controller integrity issues before using a derived disposition. For causal attribution, compare the same fixture and one policy change, or obtain an observation of the failing app. An exit code or an `EPERM` alone leaves the cause open. | Four signed file/policy contrasts and constructed controller frames. A successful command can carry withheld diagnostics. [Failed-open example](../docs/guide/PolicyWitness.md#why-couldnt-my-app-open-this-file) |
| A reader wants to use a prediction (U-04–07) | Check the query's operation and filter, planning result, `comparison.order` and the actual attempted operation. For a missing answer, look at phase collection and validator spawn evidence. A worker PID can appear for an excluded query. A validator answer with `query_first` can precede an attempt that never ran. `same_submitted` uses canonical equivalence. | Live excluded/crossed pairs, validator controls and R9 byte-association tests. In the signed example the second query and attempt concern different files and operations. [Step comparison](../docs/RESPONSE.md#predictions-attempts-and-comparison) |
| A user needs file contents, a path at open time, or a lasting effect | Choose the operation that observes it. Read the fresh descriptor and sampled bytes for contents. Distinguish the worker's descriptor path from the host's later lookup. Compare independent before/after samples for writes or transient effects. A bounded prefix can coincide on two different files. | Known six-byte read, symlink exec with only a host lookup, equal 64-byte prefixes, and interrupted creates with identical host path spellings. [Operations and phases](../docs/guide/PolicyWitness.md#choose-the-operation-and-the-phase) |
| A reader depends on exact child output (U-11) | Inspect the stream's counts, truncation and text exactness under `exec_observation.collection`. A child can print the truncation marker. Supply a text encoding in your own helper if you need to recover arbitrary binary output. | R1 exec-reader controls cover embedded NUL, invalid UTF-8 and a cut through a scalar. Replacement characters alone cannot recover the input. [Process evidence](../docs/RESPONSE.md#read-process-and-publication-evidence) |
| A reader needs the failure or ending of a worker (U-12–15) | Read the worker's structured failure and the operation's lifecycle and result source. Read the reap, kill and grace records for teardown. `cleanup_trigger` is derived at collection. `exit_requested` can be set after reap. A synthesized −1 leaves the actual return unknown. | Published compile failure, lifecycle controls, R13 scheduler mapping and interrupted/signed open contrasts. A timeout or other stop can still project an unknown termination cause. [Incomplete execution](../docs/RESPONSE.md#read-absence-and-incomplete-execution-precisely) |
| An actor operator must decide whether execution may continue (U-16–21) | Read `schedule.cancelled`, execution-wait clock evidence, and the affected actor's launch, reap and collection basis. Allowance expiry can give `runner_failed`. A setup timeout can precede launch. Treat unresolved quiescence as possible continuing execution. Ordinary final collection and an actor's visit sample phases at different times. | Actor scheduler constructed controls and the producer account. The clock-fault and late-publication contrasts do not have paired live replies. Internal `actor_unavailable` has no public field to look up. [Actor evidence](../docs/RESPONSE.md#read-actors-and-phase-ownership) |
| A user compares grants, transfer or release (U-22–26) | Put issue, delivery, consumption and the subsequent fresh open in the intended order, including within a visit. Check another actor and a pre-consumption read. To claim access after release, open anew. A held descriptor, equal raw handles, published custody, and teardown erasure each answer different questions. | Recipient-swapped fresh reads, same-visit composition and teardown controls. When an issue slot was unpublished, the reply can leave host acceptance unresolved. Last-use clearing has no public observation. [Extension evidence](../docs/EXTENSIONS.md) |

## Handing evidence to another person

| When and who | What to do and why | Basis and scope |
| --- | --- | --- |
| A recipient has a detached compiled-object receipt (U-27, U-28) | When requesting capture, choose a fresh 32-character lowercase hexadecimal nonce and keep the request separately. Match the receipt's `request_nonce` to that value. For a whole envelope, match `data.specimen.request_sha256` to the saved file bytes. Which comparison is needed depends on which object was handed over. | Three signed captures on 1666. One nonce selected exactly one input. A deliberately shared nonce selected two. Each envelope digest selected one. The host checks the worker capture. Controller receipt admission checks its labels. Neither comparison establishes authorship. [Receipts](../docs/RESPONSE.md#read-compiled-profile-receipts) |
| Someone will reproduce a run or compare compiled inputs (U-29–34) | Preserve request, fixtures, effective source, parameters and external imports as needed. Read helper `unfollowed_imports`, dossier status, each record's hash/error and the submitted-source failure. An incomplete scan may have an empty list or hashed records with errors. Use the documented framing if recomputing the closure. For `unavailable`, read worker application and completion before interpreting the missing bytes. | R12 helper contrasts, closure recomputations and the guide handoff. Changing an import or a target while keeping the request file fixed gave different worker observations. The scan and compiler read separately. Captured bytes describe the copied compiled object. [Dossier](../docs/RESPONSE.md#read-the-dossier) · [Compiler helper](../docs/RESPONSE.md#read-the-compiler-helper) |
| The reply was lost or the controller refused the frame (U-36–39) | For a retry, inspect `data.runner_client.submission`. With `invoked` or `unknown`, seek independent observations if an effect must occur only once. With an eligible actor fallback, read `actor_policy_checks` by actor/order. Read capture `status` alongside the tool exit. On `unsupported_runner_response`, inspect retained transport bytes and producer identities. | Host-loss controls, controlled fallback captures, R8/R10/R11 and transient-file trials. A fallback describes independent compilation. The same file absent at CLI return and after exit can conceal a create/unlink. [Transport](../docs/RESPONSE.md#read-invocation-and-transport) |
| A publisher or external-runner operator sees failed stdout, a warning, or `cleanup_retained` (U-41–47) | Save stderr and exit status. Check the actual fixture, registry path, owned plist and service before retrying. Use `runner list` and report-only `runner reconcile` to locate records. Use `runner remove` with the recorded selector to continue cleanup and verify absence. Preserve staging while cleanup is pending. Omit `XPC_SERVICE_PATH` or supply the canonical bundle path. | R2/R6/R7 and the final opt-in install/recovery controls. A write can fail after a mutation. A missing registry reads as empty. An inspection refusal leaves its contents unknown, and an empty reconcile report cannot certify service absence. [Runner recovery](../controller/README.md#registry-ownership-and-recovery) |

## Candidates with narrower scope

U-09 and U-10 belong to integrations that directly read validator stops or call its batch grammar. The documented stop vocabulary includes failures exercised only by source inspection. A caller that omits the value for a non-`NONE` filter gets a parse error. U-35 proposed repeating a standalone compilation as an inventory check. The recompilation has no record of which files the first compiler read, so there is no such duty. U-40's zero-length host-result scenario lacks established production reachability. U-48's validation metadata is refreshed by the implementation. Only someone who needs installation-time evidence has reason to retain a contemporaneous record. The scratch notes call for a live three-field readback before crediting that contrast.
