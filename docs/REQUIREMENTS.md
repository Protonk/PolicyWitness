# User responsibilities

The [guide draft](guide/PolicyWitness.md#responsibilities) gives the choices common to running a specimen. The table identifies when a more specific choice matters and the evidence a caller can expect from PW. The request and response references own the field meanings.

| When | What the caller supplies or decides | What the test checks |
| --- | --- | --- |
| Writing a specimen | Supply each field name once per object. Give steps distinct names you can recognize in the reply. | Both the CLI and direct host accept the repaired create request and return its step, target and policy digest. The file appears only for the admitted request. [Admission controls](../tests/suites/runner_outcome_bad_request/contract.py) |
| Comparing a query with an attempt | Choose the operation, operand, namespace and phase that ask your question. Preserve a deliberate difference when that difference is the experiment. | The crossed read controls vary the file and operation separately. The phase case collects again after unlink. [Read controls](../tests/suites/witness_contract/README.md#controlled-read-input) · [Phase controls](../tests/suites/witness_contract/README.md#public-phases) |
| Claiming an effect | Establish the relevant starting state, then observe the bytes, object or process at the time your claim concerns. For an extension, compare the recipient's fresh access before and after consumption. | Allowed and denied helper writes are checked against the marker on disk. The extension controls check the actual reads separately from delivery and consumption. [File effects](../tests/suites/run_effects/check_exec_effect.py) · [Extension controls](../tests/suites/witness_contract/check_extensions.py) |
| Using helper output as a byte record | Check `text_exact` for decoding, `truncated` for discarded bytes and `eof` for the end of the stream. | Direct output supplies the byte count and content. The literal-marker case exercises child text that happens to look like a truncation notice. [Stream checks](../tests/suites/runner_use_c_worker/check_exec_stream.py) · [Marker control](../runner/Tests/PWRunnerCoreTests/ExecStreamTextTests.swift) |
| Reproducing a run | Keep the command, specimen, result and relevant fixture bytes. Match a saved specimen to its result with `data.specimen.request_sha256`. For a policy import, check the inventory's status and the record for the file you depend on. For an incomplete scan, also read `failure` for a problem in the submitted source. | The dossier case checks file hashes and individual errors, and compares the request digest with the file the harness wrote. A worker compile diagnostic in the same run can show that the compiler evaluated a file the literal scan missed. A unit control replaces the request file during the run and requires the digest of the bytes read before it. [Dossier controls](../tests/suites/witness_contract/check_dossier.py) · [Request digest controls](../controller/src/run_flow.rs) |
| Matching a detached compiled-object receipt | Give each requested capture its own nonce. Keep the request and compare its nonce with the receipt's `request_nonce`. Reusing a nonce leaves multiple candidate requests. | The guide workflow compares the captured nonce with its saved specimen. The controller's label-admission control accepts a constructed capture whose labels are valid even when the request did not ask for it. [Guide workflow](../tests/suites/witness_contract/README.md#guide-workflows) · [Controller admission](../controller/src/run_flow.rs) |
| Repairing or repeating a run | Fix a confirmed input refusal. Once admitted, the next submission starts from the beginning. Use disposable targets when testing a repair whose real effects must wait. For a lost reply, use submission evidence and the effect's history to decide whether repetition is acceptable. An absent file at CLI return can still appear later. | The refusal and its one-field repair have independent file checks. The timeout fixture holds an invoked worker through CLI return and watches its subsequent exit. [Refusal controls](../tests/suites/runner_outcome_bad_request/contract.py) · [Timeout observation](../tests/suites/run_effects/README.md#aftermath-footprint) |
| Using an external runner | Identify the intended runner and require any entitlements the worker needs. After removal, keep the recorded bundle and recovery information while cleanup is pending. Check the warnings and reconcile the recorded service and plist. | Worker read-back governs selection. The recovery case verifies the pending record, its ownership and eventual service and plist absence. [Worker entitlements](../tests/suites/runner_byoxpc/opt_in/entitlement_readback.py) · [Recovery](../tests/suites/runner_byoxpc/opt_in/registry_recovery.py) |
