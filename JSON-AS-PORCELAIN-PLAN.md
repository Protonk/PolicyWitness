# JSON as porcelain: adoption

## Intended result

Adopt the schema-owned reply model established by the
[exploration](records/JSON-AS-PORCELAIN-EXPERIMENT.md). Swift produces fixed typed
records, the client relays opaque binary host bytes, Rust admits typed evidence,
and JSON is the public projection. Maintenance is the acceptance criterion:
ordinary evidence changes should require a schema edit and named validation,
without generic response trees or text conversion adapters. Bounded performance
costs are acceptable; no comparative performance improvement is claimed.

The [outflow agenda](records/FOOTPRINT-OUTFLOW.md#direction-2-remove-one-redundant-capture-conversion-copy)
is the associated representation work. Reception deadlines, streaming, artifact
bundles and unrelated resource-ownership changes remain outside this adoption.

## Remaining implementation and review

Use the integrated accepted source baseline recorded with the experiment. Keep
native process, publication, release and resource-ownership boundaries intact.

- Replace Swift lifecycle question maps with schema-owned run and step records.
  Normal construction supplies every named answer; incomplete evidence can retain
  a missing answer. Missing, unresolved, conflicting and inapplicable stay distinct.
- Complete typed semantic admission for fresh read/write, exec, actor
  setup/equipment/application, actor scheduling/endings and extension custody.
  Preserve raw facts when claims fail. Bound semantic list traversal as well as
  byte decoding; malformed geometry must not trigger large cross-joins.
- Retire response-only JSON coders and generic response validators after migrating
  their meaningful controls. Preserve request/control JSON, validator NDJSON,
  equipment inventory/property-list adapters and public JSON. Move encoder-only
  gates into named validation, including evidence-preserving degradation and an
  independent minimal report.
- Count equipment metadata directly as retained UTF-8 text. Version this deliberate
  reading-rule change; keep native counts and entitlement payload limits separate.
  Report frame, decoded-storage and retention budgets separately from public JSON
  size observations. A former JSON maximum does not establish a binary maximum.

The schema owns fields, tags, widths, presence and projection. Generated bindings
must remain direct and drift-checked. Keep native unknown codes representable;
recognized claims require their documented support. Do not reintroduce a generic
parser or stringify/modify/parse path to simplify migration.

## Acceptance

Build through the signed pipeline with compiler concurrency capped at two. Run
builds and native tests serially. The adoption record names the source snapshot,
commands, build identity and each credited run; local debugging is not battery
credit. No quiet-window comparison is needed because this work makes no timing
or allocation improvement claim.

Require the full default battery plus coordinated affected opt-in controls:
`runner_unit`, `runner_abi_layout`, `runner_c_worker_harness`, `failure_boundaries`,
`runner_validator_failure`, `witness_contract/order_barrier_mutations` and
`witness_contract/porcelain_output_controls`. Add actor equipment/BYOXPC coverage
when the affected capability's registered controls require it. Preserve independent
native effect, ownership and cleanup observations; successful serialization or
round trips alone do not establish semantic equivalence.

The independent Python reader must inspect actual binary receipts and reject
malformed frames, unsupported identities, conflicting associations, missing
support and incomplete output. Authored fixtures keep independent expected
outcomes. Malformed records survive claim failure as exact bytes or retained
observations, without fabricated defaults, repaired native facts or unearned
submission claims.

Review every contrary observation, rerun changed dependencies, and retain current
acceptance evidence through the repository helpers. Stop for lost evidence,
unresolved ownership or unbounded work. Once adoption is accepted, transfer lasting
behavior into the contract, implementation and resource accounts and retire this
plan and its experiment record when no dependency remains.
