**Pass.** examples-request
**Claim.** "changing the source file after admission does not change the held submission"
**Mechanism.**
CLI path (controller):
1. The request file is read exactly once, into `request_text`, at run_flow.rs 594 — before the contract gate, so "after admission" is later than the only read.
2. The parsed value is mutated in memory: `--runner-mode` injection, augment resolution, `strip_runner_selector`.
3. `held = serde_json::to_string_pretty(&request_value)` (line 696) is the single serialization. It is a re-serialization of the parsed and resolved value, not the file's bytes.
4. `held` is passed by reference to `(deps.client)` (699), which in production is `run_pw_runner_client`: it spawns `pw-runner-client … --request - <service>` and `run_with_stdin` writes `held`'s bytes to the child's stdin from a writer thread. The client is not given the file path. The Swift client reads stdin to EOF before connecting (main.swift 107).
5. The same `held` reference is passed to `(deps.policy_check)` (715, 733-735), in production `run_policy_check`, which writes it to the stdin of `sbpl-check --request -`. That runs only when `fallback_eligible()` holds for the client result. In the actor form each actor's resolved policy object, cloned from the in-memory value at 641-661, is checked separately.
6. The dossier records the request path as a string (`Specimen.request_path`); it does not record a digest of `held`.
Nothing rereads the path after step 1 (same pattern search as C:129 b; additionally `request_path` is not used after line 594 in the function body read, except as text in the dossier).
Direct XPC path: there is no controller, dossier or fallback compiler. `pw-runner-client` reads the file once with `Data(contentsOf:)` (main.swift 115) into `requestBytes` before creating the session; the session is constructed from those bytes. INFERRED: the session does not reread the path (the session class was not opened).
External runners take the same controller path; only `runner_target.service_name` and `connection` differ.
