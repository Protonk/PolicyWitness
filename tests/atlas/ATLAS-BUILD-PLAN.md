# Build an experimental Test Atlas for 0.4.0

Give the maintainer a way to ask a question of PW, inspect the experiment, and disagree with the reading. **Show where our testing apparatus has failed, or remains unable, to establish what we thought it established.** A reader should be able to find the specimen, what happened outside PW, what PW reported, and the particular assertion that could have failed. A second reader should be able to use the same material to argue for a different explanation.

Open with a question about a file PW created. Offer three departures from it, each asking what another observer could establish. Readers can enter at any question. Stop when each route has an inspectable contrast, its provenance, a reproduction pointer and a limit. Test inventory belongs in the [harness reference](../README.md). The accepted [pytest evidence work](../PYTEST-EVIDENCE-PLAN.md) owns archive-read costs and per-family blob storage.

## Build and review the routes

1. Read the raw pairs before drafting. For each question, identify the apparent proposition, the witness and sampling time, what the checker actually required, and a contrary history. Locate the failure precisely. Evidence can reveal a PW defect, an oracle accepting a contradiction, a fixture unable to observe the decisive interval, or a reader crediting a test with too much. Require an observation of product behavior before describing a product failure. Record a correction at the layer where it occurred and leave unresolved alternatives visible.
2. Prefer the identified evidence for claims about that release. For fresh evidence record the new revision, signed app and OS and check each selector with `tests/run.sh --case SUITE/CASE --list`. Use a fresh `PW_TEST_OUT_DIR=tests/out/runs/<name>` for each dispatcher invocation. The live routes need macOS, a matching app, XPC and clang. The runner unit case also requires Swift and Cargo. Use `witness_contract/happy_path_baseline` to check a new live setup and `exec_fixture/controls` for the descendant apparatus. The publication case uses `test-input run` with `--worker-kill-before-publish-slot 1` and a worker deadline. The pre-apply case uses a pre-ready delay and deadline. The seam adapter passes those controls beside the specimen. Read the actual argv in the capture. Use ordinary `run` for the uncontrolled neighbor. A future verb rename belongs to its own build. [Evidence reuse](../AGENTS.md#evaluate-and-reuse-evidence) · [Seam invocations](../README.md#seam-invocations)
3. Publish the question map as `tests/atlas/README.md`, alongside a small `evidence/` selection. Link it from the repository documentation index and the test harness introduction. The published user guide teaches operations. REQUEST and RESPONSE own public meanings, ARCHITECTURE owns the protocols, and WORKER already inventories the resources involved. Link directly to those owners. The routes need no new document graph, schema, checker or generator.
4. For each route give direct links from the question to the specimen or builder, original observations, assertion and a plausible challenge. Identify the run, build or test binding, equipment, commands, original paths, hashes and omissions. Keep raw bytes intact. Label excerpts with their file and selector and mark proposed variations as unexecuted. Keep enough of a contrary result and its context to let a reader challenge the interpretation. Preserve the original managed run and its cleanup records under their owners.
5. Verify links and anchors with the repository's Markdown reader, including the nested Atlas files. Check hashes against the original inventory, locate each cited observation without running PW, and have a reader follow one route from the raw pair to a competing explanation. Use the existing `source_drift/generator_contract` case for the documentation indexes. A green documentation check establishes link and convention checks. A claim of detection requires a recorded intervention and the relevant response. Stop at the bounded routes even if the reading suggests further investigations.
