## K-440-2 · C:440-441 · identity

**Pass.** maintenance-internal
**Claim.** "Only an annotated release tag on a clean tree can produce a release contract."
**Mechanism.** `build_contract.identity` returns `release:<tag>` only when all hold: `git rev-parse --show-toplevel` equals the root; `git status --porcelain --untracked-files=all` is empty; exactly one tag at `HEAD` matches `vN.N.N` and `cat-file -t` says `tag` (annotated); and `release_bytes_match` finds the on-disk bytes of every scoped path equal to the tag's blobs with equal path sets. More than one such tag on a clean tree raises `ambiguous release`. Otherwise `development:<digest>`. `build.sh` sets `PW_BUILD_CONTRACT` from this script unconditionally and recomputes it before signing. The Rust binary itself takes whatever nonempty `PW_BUILD_CONTRACT` its compile environment holds (`option_env!`; `build.rs` only declares `rerun-if-env-changed`), so a direct `cargo build` with the variable set compiles that string.
**Who acts.** `docs/build_contract.py`, called by `build.sh`, by Meson for the Swift context, and by release preflight — stated in the sentence: no.
**Compared with what.** Git tag type and count, `git status` output, and scoped on-disk bytes against tagged blobs. "Clean" means empty `git status` for the whole tree plus byte equality for scoped paths only — stated in the sentence: partly.
**Boundary.** Build time, before any compile, again at Meson configure, again before signing — stated in the sentence: no.
**Consequence.** Any failed condition yields a `development:` identity (or no build for two tags); release preflight then reports `build contract is not release:<tag>` — stated in the sentence: no.
**Sources.** `docs/build_contract.py` : `release_bytes_match` (39-70), `identity` (73-90), `main` (106-112); `build.sh` (251-252, 681-685); `controller/src/json_contract.rs` (10-20); `controller/build.rs` (20-28); `tests/lib/release_preflight.py` (172-177).
**Checks.** `tests/suites/source_drift/build_contracts.py` : `test_build_identity_tracks_shipped_inputs_and_requires_an_annotated_clean_release` (228) — control — default — temporary repository: lightweight tag gives development; annotated tag gives `release:v9.0.0`; an untracked file returns it to development — reaches: yes for the script. `…` : `test_source_copies_ignore_artifacts_and_release_checks_actual_bytes` (180) — control — default — an `--assume-unchanged` edit with empty `git status` gives development — reaches: yes. `…` : `test_out_of_checkout_environment_cannot_assert_a_release` (259) — control — default — `PW_BUILD_CONTRACT=release:v9.9.9` in the environment is ignored by the script — reaches: yes for the script, not for a direct Cargo build. `…` : `test_presign_contract_guard_refuses_changed_sources` (269) — control — default — extracts the guard's text from `build.sh` and runs it in a copy — reaches: partly (the guard text, not a build).
