## K-171-4 · C:171 · example

**Pass.** examples-reply
**Claim.** "an equipment hash mismatch prevents use of the claimed equipment"
**Mechanism.** Three components compare a worker binary's SHA-256 with the value recorded in the service bundle's `Contents/Resources/worker-equipment.json`; they run at different times and report differently.
Path 1, run time, actor form, XPC host (Swift), decides whether a worker is launched:
1. `ActorOrchestration` calls `ActorEquipmentPreparation.bind(bundleURL:actors:overrides:calls:)` before translating the plan or launching any actor.
2. `prepare` inspects the bundle's static code signature (`calls.inspectStatic`), records `inventory.seal_osstatus`, checks the inventory file is a regular file inside the bundle, reads it, records its SHA-256, and decodes it with `ActorEquipmentManifest.decode`, which requires `schema_version == 1`, `contract == expectedContract`, `worker_identity == PWShmLayout.abiIdentity`, exactly the two roles and fixed relative paths. 3. For each role, `bindOne` appends a binding row on every exit. 4. `executablePaths` is assigned only `if failure == nil`. So a refused row for either role, including a role no actor requested, leaves `executablePaths` nil.
