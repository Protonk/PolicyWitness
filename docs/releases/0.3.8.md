# PolicyWitness 0.3.8

The standalone guide starts with a specimen printed by the installed app and a file whose bytes you choose. Its six worked cases cover a first read, repairing a refusal, comparing failed opens, handing off a result, ordering observations into phases and deciding whether to repeat a timed-out run. The guide ships beside the ZIP. Its final table identifies the release that last changed each public contract surface.

- Use `policy-witness help result` for command outcomes and exit codes, `example` for a complete specimen bound to the build, and `test-input read --target` to prepare a read of your own file. Ordinary `run` admits and executes the specimen.
- Eight experimental worker and validator controls moved from specimen overrides to `test-input run`. Move the corresponding options to that command when reproducing timing, interruption or validator experiments. Ordinary `run` refuses the retired override keys.
- A run now reports `data.specimen.request_sha256` for the exact request-file bytes it read, including bytes it could not parse. Save the fixture and imported policy files separately. Give each requested compiled-profile capture a fresh nonce if you need to match the detached receipt to its request.
- Read per-actor policy checks for eligible fallback observations. A validator failure on a declared-unapplied actor now contributes to the outcome. A lost reply can follow an invocation that changed the target. Check submission and independent observations before repeating an effect.
- Use each JSON field name once per object. Repeated names leave acceptance and the selected value unspecified. For an incomplete import scan, inspect each file record. The summary may identify any one of several failures.
- The developer contract traces public meanings to declarations, implementations and checks, with the scope of their evidence. Review specimens against the new build contract and reinstall external services from the matching app when their equipment identity is stale.
