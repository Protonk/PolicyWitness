## K-141-1 · C:141 · example

**Pass.** examples-request
**Claim.** "a phase naming a nonexistent actor is refused"
**Mechanism.** Only the XPC host decides this; the controller has no actor-plan validation (no occurrence of `unknown_actor` in `controller/src`).
CLI path: the controller passes the contract gate, parses the selector, resolves the runner, resolves each actor policy's augments, serializes the held request and starts `pw-runner-client`, which reserves and submits to the host. From there both paths are the same.
Host: `runReservedSpecimen` decodes `PWRunnerRunSpec` (contract gate, unknown keys, field types), then calls `admit(parsed)`, which in production is `admitSpecimen`. For the actor form `admitSpecimen` checks capacity (`CWorkerOrchestrator.admissionFailure`), refuses two test-override shapes, then calls `normalizeActorPlan`. That function builds the actor table from `actors`, then walks `phases`; for each phase it requires a non-empty unique `phase_id`, a present `actor_id`, and `actors.firstIndex(where: { $0.id == actorID })`; when no actor matches it returns `fail("unknown_actor", ["phases", "<i>", "actor_id"])`. `admitSpecimen` returns `.refused(failure)`; the service replies with `requestRefusalReply` (`bad_request`, `steps: []`, `request_failure`). On the CLI path the controller publishes that reply as `data.runner_result` with exit 1.
A second call site, `requestMeaningFailure`, also invokes `normalizeActorPlan` for the actor form (ProbeRunner.swift 78); its callers were not traced. `CWorkerOrchestrator.run(parsed:)` calls `admitSpecimen` again for callers that bypass the service (CWorkerOrchestrator.swift 67). All are the same hand-written Swift function; there is no generated or Rust copy.
